# Буга-Шыдыраа · Бычьи шахматы

Тувинская настольная игра на Python и Flet 0.80.5: вдвоём за одним экраном,
против ИИ или с другом через онлайн-комнату. Интерфейс на русском,
адаптивная доска, подсветка ходов, отмена хода в локальной игре и правила внутри приложения.

Язык переключается в шапке: русский, английский или тувинский. Тувинский перевод
помечен `*`: это черновик, которому нужна проверка носителем языка. Переводятся
статусы, настройки, подсказки, правила и сообщения об ошибках; никнеймы и коды
комнат сохраняются без изменений. Переключение языка не сбрасывает партию.

На широком экране доска занимает доступную высоту окна с небольшими отступами,
включая масштабирование Windows. Заголовок, статус, управление и статистика
находятся в компактной боковой панели: смена текста не меняет положение доски.
Формы новой игры, онлайн-входа и настроек открываются отдельными окнами.

На телефоне используется отдельная компоновка: короткая шапка, ход и счётчики,
доска и нижняя панель действий. Доска рассчитывается по оставшейся высоте и ширине;
основной экран не прокручивается. Настройки открываются шестерёнкой, подробная
информация — кнопкой `i`, онлайн — значком игроков. На телефоне эти панели
открываются снизу; длинное содержимое прокручивается внутри панели. Основной
экран проверяется на размерах от 320×568 до 853×1280 логических пикселей,
включая складные устройства и планшеты. В коротком альбомном окне управление
переходит сбоку от доски. Размер поля ограничивается шириной его контейнера,
а не только шириной экрана; нулевые размеры скрытой вкладки игнорируются.

Номера узлов показаны текстом без фона ниже и правее центра. Золотая подсветка
обозначает обычный ход, коралловая с крестиком — взятие. Движение фигур анимируется,
выставление сопровождается плавным появлением. На доске отмечается последний
ход, а на время расчёта ИИ появляется полоска прогресса. Анимации можно отключить.
Фигуры, узлы и надписи сохраняют элементы Flet между ходами. Линии поля
пересчитываются только при изменении размера. Выбор фигуры отправляет обновления
свойств только изменившихся узлов, не пересоздаёт настройки и не перерисовывает
боковую панель. Появление и снятие фигур анимируются клиентом без второго
обновления через серверный таймер.

## Где выполняется приложение и хранятся переводы

Веб-версия — динамический Flet: Python, правила, ИИ, комнаты, аккаунты и выбор
строк перевода работают на сервере. Браузер запускает клиент Flutter, рисует
элементы и выполняет анимации. Нажатия и изменения интерфейса передаются по
WebSocket; при удалённом сервере время сети остаётся частью задержки отклика.
JSON-каталоги и Python-код игры целиком в браузер не отправляются.

В настольном запуске Python и клиент Flutter работают на компьютере пользователя.
Это не статическая веб-сборка с Python/Pyodide в браузере.

Переводы находятся в `src/locales/ru.json`, `en.json`, `tyv.json`. Модуль `i18n.py`
однократно читает их в память при импорте процесса. При клике или переключении
языка используются уже загруженные словари, без чтения файлов и HTTP-запросов за
переводами. Формат JSON выбран для удобства редактирования и проверки: сам по себе
он не быстрее Python-словаря, который также импортировался один раз.

Для крупных каталогов с контекстами, множественными числами и отдельным процессом
перевода можно перейти на gettext или ARB. Для текущих строк достаточно JSON;
тесты проверяют совпадение ключей и параметров во всех трёх языках.

Схема динамического веб-приложения описана в
[документации Flet](https://docs.flet.dev/publish/web/dynamic-website/).

## Запуск

Нужны Python 3.10+ и [uv](https://docs.astral.sh/uv/).
Все команды выполняются из корня проекта.

```powershell
uv sync --locked
uv run flet run src/main.py -d
```

Веб-приложение с автоматическим открытием браузера:

```powershell
uv run flet run src/main.py --web --port 8550 -d
```

Сервер без открытия окна браузера:

```powershell
uv run --extra server python src/server.py
```

Откройте http://127.0.0.1:8550 в двух вкладках. В первой нажмите «Создать комнату»,
передайте код второму игроку. Во второй введите код и нажмите «Присоединиться».
Сторону создателя определяет поле «Ваша сторона», второму достаётся противоположная.
Ходить можно после подключения обоих игроков. Гостю доступны те же партии,
что и зарегистрированному игроку. Аккаунт открывается кнопкой с именем в шапке.

Для игры с другого устройства в локальной сети:

```powershell
$env:BUGA_HOST = "0.0.0.0"
$env:BUGA_PORT = "8550"
uv run --extra server python src/server.py
```

Оба игрока открывают адрес компьютера-сервера, например `http://192.168.1.20:8550`.
Доступ зависит от настроек сети и брандмауэра. Отдельные запуски настольного
приложения не соединяются между собой: онлайн в этой версии доступен в браузере.

## Реализованные правила

- 35 узлов. Быки начинают в узлах 7 и 27, восемь мальчиков стоят вокруг центра,
  ещё 16 находятся в запасе. Первыми ходят быки.
- Бык перемещается по линии на соседний свободный узел или берёт одного мальчика
  коротким прыжком на свободный узел. Взятие необязательно, серии прыжков нет.
- Пока есть запас, мальчики только выставляют по одной фигуре на свободный узел.
  После этого ходят на соседние узлы по линиям, без взятия.
- Мальчики побеждают, когда ни один бык не может ходить.
- Сохранён порог исходного проекта: быки побеждают, когда осталось меньше
  девяти мальчиков, включая запас. Это условие приложения, а не подтверждённый
  единый турнирный стандарт.
- Ничья при третьем повторении позиции (с учётом очереди и запаса) или после
  60 полуходов без взятия, включая выставления. Взятие обнуляет счётчик.
  Условия ничьей также относятся к варианту приложения.

Сверены [описание игры Матса Винтера](https://mats-winther.github.io/bg/buga.htm)
и [материалы турнира ИРНШ Республики Тыва](https://irnsh.ru/wp-content/uploads/2022/07/Polozhenie-k-prikazu-N10-od-ot-23.03.2022-g.pdf).
У Винтера порог победы быков сформулирован как предположение; положение ИРНШ
подтверждает проведение турниров, но не задаёт подробные правила перемещения.
Поэтому спорные условия вынесены в константы движка и явно показаны игроку.

## ИИ

- Начинающий: случайный ход с приоритетом взятия.
- Сильный: итеративное углубление до 6 полуходов с бюджетом 1 секунду.
- Эксперт: до 8 полуходов с бюджетом 3 секунды.

Альфа-бета отсечения, приоритет предыдущего лучшего хода, взятий и блокировок,
оценка подвижности быков, окружения и сохранности мальчиков. Тактическое продление
ограничено двумя дополнительными уровнями. Завершённая итерация сохраняется при
исчерпании времени. Победы и ничьи оцениваются раздельно. Поиск работает на копии
игры в отдельном потоке; отмена и новая партия отбрасывают устаревший результат.
Лимит проверяется между узлами поиска и не является гарантией реального времени.
Сравнительного рейтинга силы с исходным ботом пока нет.

Интерфейс использует API закреплённой версии Flet. Проверены
[рекомендации Flet по async-приложениям](https://docs.flet.dev/cookbook/async-apps/):
фоновые задачи запускаются через `page.run_task`, вычисления — через `asyncio.to_thread`.
Переход на новую версию Flet стоит выполнять отдельно с визуальной проверкой.

Исходный `pyproject.toml` требовал `flet>=0.80.5`, а исходный lock-файл уже
содержал `0.80.5`; версия закреплена для воспроизводимости. Ветка 0.80 называлась
[Flet 1.0 Beta](https://flet.dev/blog/flet-1-0-beta/), но не является стабильной 1.0.
У новых версий есть улучшения производительности; их эффект для этой игры нужно
измерять отдельно. Сейчас миграция не выполняется.

## Хранение и ограничения онлайн-режима

Аккаунты сохраняются в `data/accounts.sqlite3` (каталог исключён из Git).
Можно указать `BUGA_DATA_DIR`; в упакованном Flet-приложении также учитывается
`FLET_APP_STORAGE_DATA_DIR`. Пароли хранятся как PBKDF2-SHA256 с индивидуальной
случайной солью и 600 000 итераций. На сервере действует ограничение попыток входа.
Вход живёт в текущей Flet-сессии; автоматического входа после новой загрузки,
восстановления пароля и проверки почты пока нет.

Комнаты живут в памяти **одного серверного процесса**. Сервер проверяет участника,
его сторону, очередь, допустимость хода и версию позиции. Состояние между
браузерами обновляется каждые 0,6 секунды. Явный выход закрывает комнату для обоих;
временный обрыв соединения не закрывает её немедленно. Возврат возможен, если Flet
восстановил ту же сессию; вход в аккаунт в новой сессии не восстанавливает место.
Неактивные комнаты удаляются при следующем обращении к сервису через 6 часов.
Лимит — 200 комнат на процесс. Перезапуск сервера теряет комнаты и партии.

В обоих веб-запусках выше используется ASGI-защита от известной ошибки
[Flet #6513](https://github.com/flet-dev/flet/pull/6513): дубликат вкладки с
скопированным идентификатором не забирает активное соединение первой вкладки,
а получает отдельную гостевую сессию. Перезагрузка после отключения сокета
восстанавливает прежнюю сессию. Адаптер привязан к протоколу 0.80.5 и должен быть
удалён при переходе на версию Flet с этим исправлением. Файлы SDK не изменяются.
Сами комнаты не дублируются: номер можно повторно открыть кнопкой онлайн.
Панели ждут завершения закрытия перед повторным использованием формы; повторные
нажатия и запоздалые события закрытия не создают несколько окон.

Это рабочая начальная версия онлайн-игры. Для публичного сервиса нужны хостинг
динамического Python-приложения с HTTPS/WSS, постоянный том для SQLite и один
worker. Статический экспорт Flet/Pyodide для этой архитектуры не подходит.
Для нескольких workers и надёжного восстановления матчей следует вынести комнаты,
сессии и партии в общее хранилище, затем добавить переподключение, историю партий,
подбор соперников, рейтинг и ограничения запросов на уровне сервера.

## Проверка и сборка

```powershell
uv run python -m unittest discover -s tests -v
uv run python -m compileall -q src tests
uv run flet build windows
uv run flet build apk
```

Тесты не требуют интернет-доступа и используют временную БД. Для сборки нужны
соответствующие инструменты платформы; установщики и мобильные пакеты отдельно
не проверялись. PyInstaller вынесен в необязательную группу `packaging`:
`uv sync --group packaging` для существующего процесса сборки через `.spec`.
При сборке PyInstaller каталоги JSON должны попасть в пакет: используйте
`--collect-data locales` либо добавьте `('src/locales/*.json', 'locales')` в `datas`
вашего `.spec`. В Flet build каталог `locales` входит в исходники приложения.
